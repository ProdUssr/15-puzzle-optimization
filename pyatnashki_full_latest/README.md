# Полная сборка пятнашек

`solver.py` — самостоятельная реализация. Вход: блоки `DATA`, `COST` в формате задания; `ORDER` во входном файле допускается, но для расчёта новой последовательности игнорируется. Цена задаётся для направлений движения плитки `U D L R`, а не для номеров плиток.

`demo.ipynb` — основная точка работы. Откройте его с рабочим каталогом `pyatnashki_full_latest`. В нём три функции: `generate_data(rows, cols, path, ...)` создаёт TXT, `solve_data(path)` решает и `check_solution(path, result)` проверяет каждый ход, стоимость и полную сборку. Размер поля задаётся аргументами `rows` и `cols` генератора. Примеры 2×3, 21×21 и 3×20 сохраняются в `examples/`.

Каждый этап установки одной или двух плиток оптимален в абстракции, где остальные свободные плитки не различаются. Окончательный блок 3×3 или 4×4 решается точно методом IDA*. Общая цена для большого поля не обязана быть глобальным минимумом. Для трудных случайных конфигураций время и память могут быть значительными, особенно для Дейкстры с двумя отслеживаемыми плитками и для IDA* на 4×4.

Перед IDA* проверяются форма остатка, правильность зафиксированных плиток и локальная чётность с перенумерацией по цели. Если внешний участок собран, неразрешимость угла означает неразрешимость всего поля. Исправить её временным перемещением внешних плиток невозможно. Решатель сообщает об этом через `UnsolvableError`, не начиная поиск. Отдельная ячейка ноутбука проверяет неразрешимые углы 4×4 и 3×3 на поле 7×7 и сравнивает их с разрешимыми примерами, полученными законными ходами.
